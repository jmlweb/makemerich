## What

`scripts/update-readme.js:87` computes the "Allocation" column of the public README positions table as

```js
const allocation = ((pos.value / STARTING_CAPITAL) * 100).toFixed(1);
```

`STARTING_CAPITAL` is the constant 5000 (`scripts/update-readme.js:17`). Allocation is a share of the current portfolio, so the denominator must be the current balance (`latest.balance.total`). `validate-rules.js:57` and `execute-signals.js` compute position percentages against the balance. Once the balance drifts from €5,000, every README percentage is wrong and the column no longer sums to 100%.

## Observed output

README.md:20-25 (regenerated by the pre-commit hook from `data/2026-10-28.json`, balance €4,558.83):

| Asset | README shows | Value / balance (correct) |
|-------|--------------|---------------------------|
| EQQQ  | 44.1% | 48.4% |
| ITX   | 22.3% | 24.5% |
| XEON  | 9.1%  | 10.0% |
| CASH  | 9.0%  | 9.9%  |
| VWCE  | 3.9%  | 4.3%  |
| TTE   | 2.6%  | 2.9%  |

The README column sums to 91.0%. Reproduce:

```sh
jq -r '.balance.total as $b | .positions[] | "\(.asset) \(.value/$b*100) vs \(.value/5000*100)"' data/2026-10-28.json
```

## Impact

The public README understates the largest position by 4.3 points. EQQQ shows 44.1%, but it is really at 48.4%, 1.6 points below the 50% single-position cap. The error grows as the balance moves away from €5,000. This fails the CLAUDE.md doc quality bar ("README ↔ portfolio.json agree").

## Fix direction

Divide by `latest.balance.total` in `formatPosition` (pass the balance in). Then rerun `update-readme.js` and check that the column sums to 100% ±0.1.
