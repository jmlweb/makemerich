# Fix: update-readme.js computes README position allocation against starting capital, not current balance

## Description

Triaged from RPT-020. `scripts/update-readme.js:87` divides each position value by the constant `STARTING_CAPITAL` (5000), not by the current balance. With balance €4,558.83, README shows EQQQ at 44.1%, but it is really 48.4%, near the 50% cap. The column sums to 91.0%. The README is public and is regenerated by the pre-commit hook. The fix is a one-line denominator change plus a regeneration.

## Acceptance Criteria

- [ ] formatPosition in scripts/update-readme.js divides position value by latest.balance.total instead of STARTING_CAPITAL
- [ ] After rerunning update-readme.js the README Allocation column sums to 100% (+/-0.1) and each row matches value/balance from the latest daily file
- [ ] node --check scripts/update-readme.js passes; validate-data.js passes and validate-rules.js is run after the change
